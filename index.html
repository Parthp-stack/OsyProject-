💡 Exam Shortcut & Banker's Tricks:
  • Monotonic Growth of Work: During the safety check, the Work vector can only increase or stay constant ($Work_{new} = Work_{old} + Allocation$). It never decreases!
  • The Deadlock Condition: If at any step the smallest Need of all unfinished processes exceeds Work, the system is permanently deadlocked or unsafe.

💡 Operating System Theory, Exam Tricks & Viva Guide

🏦 1. Banker's Algorithm: Complete Theory & Mathematical Working

What is Banker's Algorithm?

Developed by Edsger Dijkstra, the Banker's Algorithm is a deadlock avoidance algorithm used in operating systems. It is named after banking systems, where a bank never allocates available cash in a way that it cannot satisfy the maximum need of at least one customer.

Four Essential Data Structures:

  • Available Vector ($m$): If $Available[j] = k$, there are $k$ instances of resource type $R_j$ currently unassigned.
  • Max Matrix ($n \times m$): If $Max[i][j] = k$, process $P_i$ may request at most $k$ instances of resource type $R_j$.
  • Allocation Matrix ($n \times m$): If $Allocation[i][j] = k$, process $P_i$ currently holds $k$ instances of resource type $R_j$.
  • Need Matrix ($n \times m$): $Need[i][j] = Max[i][j] - Allocation[i][j]$. Indicates remaining resources $P_i$ may need to finish execution.

The Safety Algorithm:

  1. Let $Work = Available$ and $Finish[i] = \text{false}$ for all $i = 0, 1, \dots, n-1$.
  2. Find an index $i$ such that:
    • $Finish[i] == \text{false}$
    • $Need[i] \le Work$
    If no such $i$ exists, go to Step 4.
  3. $Work = Work + Allocation[i]$, $Finish[i] = \text{true}$, append $P_i$ to Safe Sequence. Repeat Step 2.
  4. If $Finish[i] == \text{true}$ for all $i$, the system is in a SAFE STATE. Otherwise, it is UNSAFE.
📄 2. Paging & Page Replacement Algorithms: Detailed Working

What is Paging?

Paging is a memory management scheme that eliminates the need for contiguous physical memory allocation. Logical memory is divided into fixed-size blocks called Pages, and physical memory is divided into same-sized blocks called Frames.

Page Fault (Miss) vs Page Hit:

  • Page Hit: The referenced page is already resident in one of the physical memory frames. Memory access proceeds with zero I/O delay.
  • Page Fault: The referenced page is not present in physical memory. The OS traps to kernel mode, initiates disk I/O to bring the page from backing store, and if frames are full, executes a Page Replacement Algorithm to evict a victim page.

The Three Page Replacement Algorithms:

  • FIFO (First In First Out): Replaces the page that was brought into memory earliest. Low implementation overhead (uses a queue), but may evict heavily used pages and suffers from Belady's Anomaly.
  • LRU (Least Recently Used): Replaces the page that has not been referenced for the longest period in the past. Requires hardware support (counters or stack) and never exhibits Belady's Anomaly.
  • Optimal (OPT / MIN): Replaces the page that will not be used for the longest period in the future. Has the theoretical minimum possible page fault rate; used as an analytical benchmark because future references cannot be known in general-purpose OS.
🎯 3. High-Yield Viva & Exam Questions (with Ideal Answers)

Q1: What are the four Coffman conditions for deadlock?
Answer: 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait. All four must hold simultaneously for a deadlock to occur.

Q2: What is the difference between Deadlock Prevention and Deadlock Avoidance?
Answer: Deadlock Prevention eliminates deadlocks by ensuring that at least one of the 4 Coffman conditions can never hold. Deadlock Avoidance dynamically monitors resource allocation state (like Banker's algorithm) to ensure the system never enters an unsafe state.

Q3: What is Belady's Anomaly and which algorithms suffer from it?
Answer: Belady's Anomaly is the phenomenon where adding more page frames leads to an increase in page faults. It can occur in FIFO, but never in Stack algorithms like LRU or Optimal.

Q4: What is the Convoy Effect in CPU Scheduling?
Answer: In FCFS scheduling, when a CPU-intensive process with a large burst time executes, all shorter I/O-bound processes are forced to wait behind it, causing severe drop in CPU and device utilization.

Q5: What is Thrashing in Virtual Memory?
Answer: A state where the CPU spends significantly more time swapping pages in and out of backing store (paging activity) than executing user processes, causing CPU utilization to collapse to near zero.
